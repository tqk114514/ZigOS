# ADR-0017：M2 遗留清理——堆统计与 syscall 句柄

- 状态：已接受
- 日期：2026-10-23
- 关系：ADR-0016 的后续清理；M3 前置。每线程内核栈与 guard page 留待 ADR-0018。

## 背景

宪章要求内核堆“有上限、可统计”，当前只有上限；syscall 的 `write` 仍使用魔法句柄 1，没有经过 object 的引用/权限/代际检查，句柄边界实际未闭合。

## 决策

1. **堆统计**：`Heap.stats()` 在堆锁内返回 `live_blocks`、`live_bytes`（含块头与对齐）与 `capacity_bytes`（固定 256 MiB）；alloc/free 维护计数。`kernel-mem` 断言压力循环前后计数不变、活跃块与字节数合理。配额即固定容量，超过时分配返回 null（现有行为）。
2. **句柄接入**：`write` 走 `object.HandleTable`：内核在启动时创建 console 对象并插入句柄表（write 权限），把句柄值下发给 arch 以嵌入用户程序；syscall 分派改为 **arch 注册钩子 + kernel 模块实现**（DAG：arch 不能依赖 object）。分派器先做长度上界检查，再 `lookup(handle, write)` 校验代际/权限/对象种类，随后只经 `copyFromUser` 读取参数。
3. **自检**：启动时插入一个临时句柄、验证可解析、移除后验证不可解析（代际失效），失败即 panic（不变量破坏）。
4. **当前限制**：句柄表是**内核全局**的 console 表；每进程句柄表随进程对象化（M3 前置）迁移。句柄值假设 ≤ 255 才能用 5 字节 `mov edi, imm32` 指令嵌入程序；smoke 断言这一点，超出即失败。

## 后果

- “可统计”与“句柄边界”两项关闭；syscall 不再依赖魔法常量。
- 追加统计使 `heap_churn` 增加约 31%，基线按 ADR-0009 程序单独刷新。
- 下一增量：每线程内核栈 + 栈 guard page + 线程槽位回收（ADR-0018），随后 M3。

## 被否决的选项

- **在 arch 里直接引用 object**：违反依赖 DAG。
- **保留魔法句柄 1**：无法检测悬垂/伪造句柄。
- **统计按需开关**：ReleaseSafe 也必须有统计，关掉就只是测试道具。
