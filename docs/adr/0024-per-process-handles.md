# ADR-0024：每进程句柄表

- 状态：已接受
- 日期：2026-10-24
- 关系：ADR-0014 的对象/句柄、ADR-0021 记录的遗留、ADR-0023 的地址空间回收。

## 背景

句柄表至今是内核全局的：所有用户代码共享控制台与文件句柄，任何用户进程都能使用别的执行流创建的句柄。ADR-0021 把它记为遗留。spawn/exec 之前需要先把“进程”变成真实的所有权单位。

## 决策

1. **Process 结构**：一个进程持有可选的地址空间、一个私有 `HandleTable`（容量 64）与控制台句柄。文件状态仍来自全局 8 槽静态池，因此“每进程句柄隔离”不会把打开文件总数变成无界。
2. **当前进程是 per-CPU 的**：用户代码运行时，本 CPU 的 current 指针指向其进程；syscall 分发只通过当前进程的表解析句柄。没有当前进程时一律拒绝，不设内核回退表。
3. **生命周期**：调用者创建/装载地址空间，`create()` 收养空间并插入控制台句柄；用户代码返回后 `leave()` 清除 per-CPU 指针，`destroy()` 先 `drain()` 所有句柄（释放文件槽），再回收地址空间，最后归还进程槽。进程池固定 4 槽。
4. **测试夹具显式挂进程**：用户冒烟的 hand-written 程序使用一个无地址空间的测试进程；A2 的工作线程在 CPU 1 上创建自己的无空间进程。程序里固化的控制台句柄在每个新表里都是 0，`beginTest()` 同步更新 `setConsoleHandle`。
5. **控制台对象是内核全局的**，每个进程把自己的表 slot 0 指向它（read|write 权限）。
6. **验证**：进程自检创建两个进程，验证 A 的句柄在 B 中不可解析；shell 在进程内运行并保留帧数回收断言；`kernel-user` 的全部用户程序都在测试进程下执行；QEMU 断言 `PROCESS: isolation ok`。
7. **不在本增量**：进程句柄、spawn/exec、线程迁移时的进程重挂、每进程文件配额。

## 后果

- 真实用户进程（shell）拥有私有句柄命名空间；文件总数仍由全局槽池约束。
- 进程槽是固定上限；spawn/exec 需要扩展池与进程对象句柄。
- 当前进程指针按 CPU 维护；用户线程若迁移 CPU，需要线程携带进程并在切换时重挂（留给 spawn/exec）。

## 被否决的选项

- **每进程文件槽池**：打开文件总数会随进程数无界增长，违反资源有界。
- **内核回退表**：会掩盖“用户代码没有挂进程”的接线错误。
- **线程自带句柄表**：现在没有线程到进程的稳定映射；先把进程建成所有权单位。
