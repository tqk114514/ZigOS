# ADR-0001：内核形态与 v1 范围

- 状态：已接受
- 日期：2026-10-23
- 决策者：项目作者

## 背景

项目目标是用 Zig 写一个“不是学习型内核、也不是完整 OS”的严肃内核核心。约束是：

- 现代化，但拒绝已被淘汰的接口；
- 性能可度量；
- 模块化、可扩展，避免逻辑耦合；
- 代码质量与测试优先；
- 单人可持续，完整内核不现实。

这些目标之间存在取舍。最大的分歧是内核形态：模块化宏内核、微内核还是混合内核。

## 决策

1. **采用模块化宏内核。** 单一内核地址空间，模块间单向依赖，驱动只依赖 HAL，功能按 comptime 裁剪。对象/句柄模型为未来把服务迁到用户态保留边界，但 v1 不实现 IPC 微内核。
2. **第一平台是 x86_64 + UEFI + QEMU/virt。** 使用 Limine、APIC/x2APIC、IOAPIC、TSC/HPET、PCIe ECAM、MSI-X、virtio。禁用 BIOS/PIC/PIT/PS/2/VGA text/IDE/8259。
3. **v1 的范围是内核核心。** 里程碑 M0 启动、M1 内存与中断、M2 SMP/调度/对象/syscall/用户态、M3 VFS/initramfs/virtio-blk/shell。网络、可写文件系统、真实硬件、多架构在 v1 之后。
4. **syscall ABI 自定义。** 句柄 + spawn/exec；不做 fork、signal、POSIX 兼容层。
5. **SMP 与测试从第一天就是默认。** 单核只是测试配置；host 单测、QEMU 集成、fuzz 三层测试进入 CI。
6. **依赖图与接口边界可执行。** 跨模块只能导入 `<module>/interface.zig`，反向依赖由 `zig build check-deps` 拒绝。

## 后果

正面：

- 性能路径直接，不需要为 IPC 和用户态驱动支付固定成本。
- 单人可维护：模块边界清晰，构建期裁剪，调试路径短。
- 依赖图、std 禁用清单、import 规范可以自动检查，宪法不是口号。
- 未来仍可把文件系统、网络等服务迁到用户态，因为对象/句柄模型已经预留边界。

负面：

- 故障隔离弱于微内核；驱动崩溃会影响整个内核。
- 模块边界靠纪律和 CI 维持，不靠硬件隔离。
- “现代化”被限定为负向清单，不能靠引入新架构名词来规避工程成本。

## 被否决的选项

- **微内核**：隔离和模块化最彻底，但 IPC、用户态驱动、DMA 授权会让 v1 晚很多；性能需要很深的手工优化。与“性能 + 单人可持续”冲突。
- **混合内核**：早期就要维护内核态/用户态两套边界，复杂度最高。
- **POSIX 兼容**：把大量历史接口和语义带入 v1，和“拒绝落后技术”冲突。
- **学习型玩具内核**：不满足性能、模块化和测试目标。
- **先单核跑通再补 SMP**：SMP 改造会污染内存管理、调度、锁和驱动；代价远高于从第一天按 SMP 设计。
