# ADR-0018：M2 遗留清理——每线程内核栈与 guard page

- 状态：已接受
- 日期：2026-10-23
- 关系：ADR-0017 的后续；M2 遗留的最后一项。

## 背景

线程栈目前是 `.bss` 里的静态数组，彼此相邻且没有 guard page：一次越界写会静默破坏相邻线程的栈；`threadExit` 也不回收槽位，线程表只减不增。

## 决策

1. **带 guard 的内核栈窗口**：`0xffff_d000_0000_0000` 起，每个线程 id 一个 20 KiB 步长：低 4 KiB 为**不映射**的 guard page，紧接 16 KiB 栈（4 页，RW/NX）。窗口在首次启动调度器时（BSP）一次性映射好（24 个线程 × 4 页 = 96 帧），之后各 CPU 只按 id 取用。
2. **每线程独立栈**：工作线程/用户入口线程使用窗口内的栈；boot 控制线程继续用镜像里的启动栈，idle 线程保留各自的 4 KiB 静态栈（无 guard，属已知小缺口）。
3. **槽位回收**：`threadExit` 在切走前把自身挂到本 CPU 的 `reap` 槽（队列锁内），随后切入 idle；idle 循环在下次停车前持池锁把 `reap` 槽位清回 `free`。此时栈已不在使用，可安全复用；窗口映射按 id 复用，无需解映射。
4. **guard 证据**：`kernel-sched` 在启动时断言每个线程 id 的 guard page `translate == null`、栈底 `translate != null`；越界会以内核态 #PF 致命退出（不可静默）。
5. **限制**：guard 只保护栈窗口内的线程（boot/idle 栈除外）；线程栈大小固定 16 KiB；用户态系统调用的入口栈仍是每 CPU 固定栈（与线程栈分离）。

## 后果

- 线程栈越界从“静默踩内存”变为“确定性别名 #PF”；线程槽位可以循环复用。
- 映射开销固定（96 帧 + 页表），不随线程数增长。

## 被否决的选项

- **按需分页线程栈**：首触缺页会在 IRQ/系统调用入口前发生，M2 调度器没有可睡眠的分配路径。
- **静态数组外加 MPU/页表技巧**：窗口方案更简单且与现有 paging 原语一致。
- **线程退出时立即解映射**：退出路径仍在该栈上运行，必须延后到切换之后（本次用 idle 回收实现）。
