# ADR-0023：用户地址空间回收

- 状态：已接受
- 日期：2026-10-24
- 关系：ADR-0021 附记记录的遗留；ADR-0006 的页表分配。

## 背景

M3 的 shell 与用户冒烟在程序退出后不回收地址空间：用户页、各级页表与 PML4 帧全部泄漏。ADR-0021 把它记为已知遗留；v1 之后继续扩展用户态前必须补上确定性的回收路径。

## 决策

1. **所有权显式**：`create()` 的调用者拥有地址空间；`runUser` 只切换并恢复 CR3，不销毁。销毁必须发生在空间不再被任何 CPU 使用之后（调用者等待用户线程退出）。
2. **只回收低半区**：用户 PML4 的 `0..255` 项归用户空间；遍历并释放叶子 4 KiB 页、PT/PD/PDPT 页表帧，最后释放 PML4 帧。`copyKernelEntries` 复制的高半区项与内核共享，绝不释放。
3. **仅 4 级**：`create()` 已拒绝 5 级页表；用户映射只用 4 KiB 页。遍历遇到 PS 位视为不变量破坏，跳过而不是把被当作页表的物理页释放。
4. **锁序**：遍历持 paging 锁；释放帧时按文档顺序 `paging → frame` 取 frame 锁。
5. **调用点**：`runShell` 在成功、加载失败与栈映射失败路径都销毁；用户冒烟的空间 A 与 A2 空间 B 在退出后销毁；新增一个 `create → map → destroy` 周期，断言空闲帧数回到基线。`kernel-shell` 分支断言运行前后空闲帧数一致并打印 `SHELL: space reclaimed`。
6. **TLB**：销毁前 CR3 已切回内核（无 PCID，写 CR3 即刷新非全局项）；销毁后不会有 CPU 再以该 PML4 运行。

## 后果

- 地址空间生命周期的遗留关闭；用户程序可以反复运行而不泄漏帧。
- 每进程句柄表、virtio 完成中断/MSI-X、host 覆盖率工具仍是后续工作。

## 被否决的选项

- **在 `runUser` 内自动销毁**：测试与后续执行需要在恢复内核上下文后检查空间，隐式销毁会限制调用方。
- **引用计数自动销毁**：当前没有进程对象持有空间，计数只会增加复杂度。
- **释放高半区项**：那是内核共享页表，释放会破坏所有地址空间。
