# 项目宪法

版本 1.0 · 2026-10-23 · 状态：生效

这份文档定义项目是什么、不做什么，以及哪些红线不能被“先跑起来”绕过。它刻意写得短；实现细节属于 `ENGINEERING.md` 和 `ARCHITECTURE.md`。三者冲突时，以本文件为准。

修改本文件必须先写 ADR，再改文本，并更新版本号。例外必须记录在案、指定负责人和失效日期；没有失效日期的例外视为未批准。

## 1. 定位

本项目是一个面向 QEMU/virt 的 x86_64 内核核心，使用 Zig 编写。

目标是可验证、可演进、性能可度量、模块边界可检查的现代内核。它不是 OS 发行版，不是 POSIX 实现，也不是教学示例；用户态只保留验证内核 ABI 所需的最小集合。

## 2. v1 完成定义

v1 的完成定义是 M3 全部通过 CI 矩阵。里程碑是验收物，不是日期：

- **M0 启动**：UEFI/Limine 启动、串口日志、panic + backtrace、QEMU smoke。
- **M1 内存与中断**：异常/中断、APIC 时钟、物理/虚拟内存、按需分页、内核堆。
- **M2 并发与用户态**：SMP、per-CPU、抢占调度、对象/句柄、syscall、用户态。
- **M3 存储与外壳**：VFS、只读 initramfs、virtio-blk、用户态 shell（串口 TTY）。

v1 之后的第一批工作是 virtio-net 与 ARP/IPv4/ICMP/UDP；TCP、可写文件系统、更多驱动排在其后。任何里程碑的范围变更都走 ADR。

syscall ABI 自定义：句柄 + spawn/exec，不做 fork、signal 或 POSIX 兼容层。

## 3. 非目标

v1 明确不做：

- POSIX/Linux 二进制兼容、fork、signal。
- GUI、音频、USB 栈。
- 真实硬件支持、多架构支持。接口保持可移植，但这两项不是 v1 验收项。
- 内核模块热加载、微内核 IPC。
- 任何“先跑起来再清理”的全局状态、临时分配器或调试旁路。

非目标不是能力上限，而是拒绝 scope creep 的边界。越过边界需要 ADR。

## 4. 平台与现代化

第一目标平台：x86_64 long mode、UEFI、QEMU/virt。

禁用已被淘汰的接口：BIOS/real mode、PIC/PIT、PS/2、VGA text、IDE/ATA、8259。

使用：Limine、APIC/x2APIC + IOAPIC、TSC/HPET、PCIe ECAM、MSI-X、virtio。

成熟标准（ACPI、PCIe、virtio）不因“老”被拒；只有死路才进禁用清单。现代化是负向清单，不是对新名词的追逐。

## 5. 架构

模块化宏内核：单一内核地址空间，模块间单向依赖，驱动只依赖 HAL，功能按 comptime 裁剪。

依赖图与接口边界见 `ARCHITECTURE.md`，由 `zig build check-deps` 强制。反向依赖、跨模块绕过接口、外部包依赖都是构建失败。

SMP 从第一天就是设计常态：per-CPU 数据、无 BKL；单核只是测试配置，不是设计假设。

对象/句柄模型为未来把服务迁到用户态保留边界，但 v1 不实现 IPC 微内核，也不动态加载模块。

## 6. 内存、失败与并发

所有分配显式传入 allocator；内核堆有上限、可统计；IRQ 上下文禁止分配。

用户指针永远不可信：跨边界访问只能经过 copy_from_user/copy_to_user，校验长度、对齐和溢出。

可恢复错误走 error union；panic 只用于不变量破坏。内核态不得“尽力继续”。

锁序文档化；IRQ 上下文不睡眠、不等待；硬件等待有超时；资源有界且可统计。

## 7. 性能

热路径（syscall、调度、IPI、页错误）零分配、无无界循环、无意外的 O(n) 工作。

性能由基准证明：基准进 CI，相对基线回归超过阈值即失败。QEMU 的绝对值不作数，真实硬件后置验证。默认回归阈值为 5%，调整阈值需要 ADR。

关闭 runtime safety 只允许在有基准证据的审计点，并写 ADR。

## 8. 质量与测试

代码规则见 `ENGINEERING.md`；其中的测试与提交规则同样具有约束力。

测试三层：host 单测、QEMU 集成、fuzz。每个 bug 修复先有失败测试。

任何提交必须通过 `zig fmt --check .`、`zig build test`、`zig build check-deps`；M0 起增加 QEMU smoke。

覆盖率只对 host 可测代码设门槛（工具就绪后下限 80%）。内核路径靠启动矩阵（smp 1/4 × Debug/ReleaseSafe）和 fuzz 判断，不靠行覆盖率。

## 9. 变更纪律

一个提交一个逻辑变更；重构与行为变更分离；每个提交可构建、可测、可独立回滚。

提交消息写“为什么”和实际执行过的验证。AI 辅助生成的改动适用同一标准；提交者承担验证责任，“模型说可以”不构成证据。

架构决策写 ADR。CI 未通过的工作不进入主分支。

## 10. 工具链与依赖

Zig 版本钉死 0.17.0（CI 固定版本；`build.zig.zon` 记录最低版本）。

升级是独立变更：一个 ADR，说明破坏性改动、迁移范围和全矩阵结果。

内核禁止 libc、动态链接和外部包；新增依赖需要 ADR。

## 11. 修订

修改本文件：先写 ADR，后改文本，再更新版本号。

例外：记录在 ADR 或提交中，写清负责人和失效日期；到期必须续期或删除例外代码。没有记录在案的例外不成立。
